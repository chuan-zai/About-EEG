# EEG 项目操作台使用指南

本指南对应仓库 `work` 分支的 Web 操作台。适合首次接手项目、在本机检查数据、在朋友的 GPU 主机执行短程验证的使用者。页面按钮名称与当前实现一致；文中的命令需在项目目录执行。

## 1. 先理解操作台运行在哪里

操作台是本项目的网页界面，服务、数据和训练进程运行在同一台主机。浏览器只是显示界面，不提供计算资源。例如：在朋友的 GPU 电脑启动服务，再从自己电脑访问，训练使用朋友电脑的 GPU。

操作台需要 Python 和项目依赖，不需要 Node.js 或数据库。默认地址为 `http://127.0.0.1:8765`。每个项目目录只启动一个操作台实例，一次只能执行一个任务；浏览器关闭后，主机上的任务通常继续运行。

当前研究是 8ch/22ch 混合自监督训练对完整 22ch 重建的影响。模型选择只能用 T 训练/验证，E 用作最终测试；分类不是主终点，不预设负迁移。本阶段不要启动全量正式实验，也不要实现梯度保护。

**第一次使用建议顺序：启动 → 查看概览 → 运行测试 → 下载 S01 → 查看审计 → S01 四步冒烟 → 按需接入 S02–S09。** 生成正式计划与启动正式训练是后续独立步骤。所有下载和计算由点击按钮明确触发，启动服务本身不会训练。

## 2. 获取完整项目

首次获取，在终端执行：

```bash
git clone --branch work https://github.com/chuan-zai/About-EEG.git
cd About-EEG
```

已有项目时，先停止正在执行的任务，再检查并更新：

```bash
git status
git switch work
git pull --ff-only origin work
```

若有本地未提交修改或快进更新失败，先保留并处理本地工作，不要使用强制重置。运行中更新源码会让任务的代码版本难以追踪。

项目根目录应同时含有 `pyproject.toml`、`eeg_transfer/`、`configs/`、`reports/`。只有启动 ZIP 不能代替完整项目。

Git 不包含真实 EEG、模型权重、正式大计划和虚拟环境。即使仓库带有九人审计报告，刚克隆后仍可能显示数据缺失。这不等于报告丢失，也不等于当前已重新核验数据。

## 3. 安装与启动

### 3.1 Linux / WSL2：推荐的完整任务管理环境

建议 Python 3.12（项目最低要求 3.10）。使用独立虚拟环境，不复制其他电脑的 `.venv`：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pip check
.venv/bin/python -m eeg_transfer.console
```

若命令找不到 `python3.12`，先安装可用的 Python，或用已确认版本的 `python3` 创建环境。上述 PyTorch 命令用于 CPU；GPU 主机请按第 12 节安装对应版本，不要先强制安装 CPU 版。

成功启动后，终端会显示类似：

```text
EEG Console: http://127.0.0.1:8765
Access token: <本次启动生成的令牌>
```

保留该终端窗口，在浏览器打开显示的 URL。启动脚本不会自动打开浏览器。

如果端口被占用，先检查是不是已有服务；也可换端口：

```bash
.venv/bin/python -m eeg_transfer.console --port 8766
```

此时访问 `http://127.0.0.1:8766`，SSH 转发端口也要相应调整。

### 3.2 Windows 一键启动

1. 安装 Python，推荐 3.12，并确保有 Python Launcher（`py`）或 PATH 中的 `python`。
2. 获取完整 `work` 分支，解压或克隆到如 `E:\About-EEG`。
3. 在项目根目录双击 `START_CONSOLE.cmd`。
4. 脚本创建 `.venv`、检查依赖；缺少依赖时安装，首次运行可能需数分钟及网络访问。
5. 看到 `Access token` 后，手动打开 `http://127.0.0.1:8765`。
6. 保持黑色命令窗口打开。退出服务使用 Ctrl+C，并注意第 11 节的任务退出限制。

也可以从 `downloads/EEG-console-launcher.zip` 解压启动脚本。若脚本不在项目根目录，运行时输入完整项目路径，不是 `.venv` 路径。ZIP 仅含启动工具和说明。

脚本不修改旧 `bci_env`，不配置 CUDA，不自动训练。发现无效 `.venv` 会提示手动重命名，不会自动删除；Linux 虚拟环境不能直接用于 Windows。

**平台限制：** 一键脚本尚无 Windows CMD 实机验证。后端停止任务使用 `os.killpg` / SIGTERM，完整任务管理面向 Linux/WSL2；原生 Windows 不应依赖网页“停止”功能管理正式训练。需要可靠的任务停止和 GPU 长时间运行时，建议使用 WSL2 或 Linux，并在该环境内独立安装依赖。

## 4. 登录、令牌与连接

1. 打开网页，弹出“连接项目操作台”。
2. 复制服务终端中 `Access token:` 后面的完整内容，不包含前缀或空格。
3. 粘贴到“访问令牌”，点击“连接工作区 →”。
4. 左下角出现“工作区已连接”，概览显示实际项目路径，说明连接成功。

右上角“访问令牌”可重新输入，“↻ 刷新”可手动更新。页面通常每 5 秒拉取一次状态；无需反复点击任务按钮。

默认令牌每次启动重新生成，保存在服务内存和当前标签页的 `sessionStorage`。服务重启或新开标签页后可能需要重新输入。管理员可通过环境变量 `EEG_CONSOLE_TOKEN` 设置固定令牌，但不要把实际令牌写进脚本、截图或 Git。

只在本机或通过 SSH 转发访问。不要直接将此 Python 服务以 `0.0.0.0` 暴露到公网；操作台不是多用户托管服务，也不提供 HTTPS 或账户管理。

## 5. 项目概览：每个数字代表什么

| 显示项 | 含义 | 不能据此认定 |
|---|---|---|
| 真实数据 n / 9 | 该受试者 T/E MAT 和处理后 NPZ 都存在 | 文件哈希、单位、内容已重新验证 |
| 已恢复配对计划 | 所选概览清单中，计划路径存在的运行描述数 | 已执行相应训练；270 描述对应27个计划包 |
| 正式结果已完成 | 清单输出目录的 status 为 complete 的计数 | 所有评价完整、统计可以推断 |
| 控制台运行任务 | 操作台记录的 running 任务数 | 全主机没有其他训练进程 |
| GPU / DEVICE | nvidia-smi 返回的信息，或未检测到提示 | 训练必定使用 CUDA |

概览会自动选取一个有可用计划的清单，选择依据是路径顺序与可用性，不是科学版本审核。实际操作时在“实验计划”中明确选择清单，查看完整路径，不要只看概览数字。

历史 `ready=true` 和学习门槛是历史证据。当前恢复状态以本机数据、计划、测试和新审计为准。

## 6. 数据与审计：逐个下载、检查

进入左侧“数据与审计”，每行对应 S01–S09。

### 6.1 下载并接入一名受试者

1. 首先确认该行“派生 NPZ”为缺失；已有 NPZ 时按钮禁用，后端也会拒绝覆盖。
2. 首次只操作 S01，点击该行“下载并接入”。
3. 自动跳转“任务与日志”，查看状态和输出。等待完成后再启动其他任务。
4. 下载器获取该受试者 T/E 两份官方 MAT；已有原始文件不重复下载。
5. Worker 对照历史审计核验原始 SHA256，再转换为规范数据，并拟合仅基于 T 训练 trial 的归一化。
6. 状态“已完成”、退出码 0 后，返回数据页刷新，确认原始与派生文件存在。
7. 查看任务详情中的审计 JSON，或在输出目录读取 `audit.json`。

下载地址为 BNCI 官方 MAT，可能重定向到 Graz 主机。网络需要允许 `bnci-horizon-2020.eu` 和 `lampx.tugraz.at`。数据遵循原来源许可与署名要求，不能把处理后 EEG 默认作为可公开再分发文件。

成功判据不只是一行绿色状态：还应核对审计中的22 EEG（无3 EOG）、250 Hz、uV→V、cue为trial起点+2秒、[2,6)秒1000点、官方伪迹剔除记录、T/E身份与split。先通过S01验证再逐人下载S02–S09。当前界面没有“一键九人全下载”按钮。

### 6.2 查看审计与重新审计的区别

- “查看审计”：读取已保留的受试者审计，可能来自历史环境；不重新读信号或核对哈希。
- “重新审计”：只读本地 `data/raw/AxxT.mat`、`AxxE.mat`，不下载。重新转换到 `data/console/<任务ID>.npz`，写入独立 `reports/console/<任务ID>/audit.json`。
- 重新审计不会替换 `data/processed/Sxx.npz`，也不是修复缺失规范数据的按钮。只有 MAT、没有规范 NPZ 时仍可用“下载并接入”，它会复用已有 MAT。

数据页的历史划分数字来自已有审计，不一定自动切换为刚生成的 `audit.json`。新审计请从该任务详情查看。已有规范NPZ但原始MAT缺失时，“重新审计”禁用、“下载并接入”也会拒绝覆盖，应由维护者单独恢复原始文件，而不是删除数据来绕过保护。

### 6.3 下载失败怎么办

在任务详情查看错误全文；不要立即多次重试。CONNECT 403说明当前环境代理阻止连接；网站返回404、超时、SHA不匹配是不同问题。SHA不匹配应保留文件与新审计，不修改历史期望值求通过。下载过程使用临时文件并在失败时清理，不把残缺MAT当完整数据。

如果下载成功但转换失败，可能留下原始文件或部分派生文件。先检查日志与文件，不要直接删掉或覆盖；继续恢复前应确认哪些数据通过了核验。

## 7. 协议与配置：只读核对

点击“协议与配置”，再点击左侧具体文件查看原文。页面不会修改科研参数。

重点检查：

- `configs/rq1-suite.json`：正式V2 dim64、2层、patch5；time/stride250，batch4，1000基础更新，AdamW lr=.001、wd=.01。
- 配对训练seed42/43/44；split_seed42；固定评价maskseed1101/2202/3303。
- `reports/phase3/protocol-lock.json`：历史锁定值与代码哈希。
- `reports/phase3/statistical-protocol.md`：元素汇总RMSE、受试者级差异、CI、Holm多重比较与区域解释。

8ch固定Fz/FC3/FC4/C3/Cz/C4/CPz/Pz，其余14ch不能进入该训练样本输入或监督。random25区域指标与独立outside14协议不可混合。修改模型/协议需要新版本与重新验证，不能为了匹配历史数值改变配置。

## 8. 运行测试和四步冒烟

### 8.1 自动测试

在“项目概览”点击“运行测试”，或在“任务与日志”点击“运行全部测试”。实际执行 `python -m pytest -q -ra`，使用启动服务的同一个Python。

任务完成后，记录日志末尾实际 passed/skipped/failed 数量及退出码。**任务失败不一定是模型错误**：从Git恢复了清单却没有被忽略的大计划时，某些集成测试会因FileNotFoundError失败；缺数据测试也可能skip。保留真实结果，不照抄历史38通过。

测试可能包含固定的E单trial工程回归，其结果不进入模型选择。该入口不启动全量正式实验。

### 8.2 S01四步冒烟

前提是 `data/processed/S01.npz` 可用且已审计。点击“4步冒烟 →”或“S01 · 4步冒烟”。

当前固定行为为V2/A2、seed42、4次更新、只评价预先限定的1个T验证trial、不评价E；使用正式模板的其他参数，独立输出，不改协议锁。它用于检查训练与评价管线，不是重跑V1/V2学习gate，不是负迁移实验。

成功判据：状态complete、退出码0；日志/曲线有4次更新，loss和梯度有限；输出有 `status.json`、`train.jsonl`、`manifest.json`、`evaluation.json`，评价中不含 `test_*`。没有loss曲线的数据下载、审计和测试任务属于正常情况。

## 9. 实验计划与结果汇总

### 9.1 生成新配对计划，不训练

九人规范数据齐备并通过核验后，在“实验计划”点击“生成新配对计划”。

这会按固定配置生成9人×3seed的27个gzip包，以及270个正式运行描述，分别写入新的计划、报告与结果路径。生成计划会读E数据以固定评价trial/window/mask，但不评分或用E选择模型。此步骤可能耗时并占用存储，仍受一次一个任务限制。

完成后返回实验页，从下拉框选择新生成的 `reports/console/<任务ID>/rq1-manifest.json`。不要因为列表中存在历史清单就认为相应gzip包已经恢复。新的压缩包字节hash可能不同，需与历史事件与评价mask作语义核验，不改写旧hash。

### 9.2 浏览清单

1. 选择具体清单，核对旁边“可用计划数/总数”。
2. 用“全部受试者”和“全部实验组”下拉框筛选。
3. 核对运行标识，例如 `S01-seed42-A0`，种子和组别。

筛选只改变显示，不会改变实验配置或启动任何任务。列表中的“启动单项”不代表该项已经通过全部科学准备检查。

### 9.3 汇总结果

选中正确清单，点击“汇总此清单结果”，然后在任务详情展开“评价 / 审计 / 汇总 JSON”。

结果不齐时应看到 `complete=false`、缺失运行列表和 `statistics=null`。汇总任务本身可以complete，表示程序成功检查了缺失情况，不代表270项正式实验完成。禁止仅挑成功seed或最好重跑作正式推断。

### 9.4 单项正式训练：仅在另行授权后

**当前用户尚未要求启动正式训练；日常检查不要点击执行。** 以下为未来操作说明：

1. 完成数据/计划/协议/环境核验，确定使用经过审核的新清单。
2. 选择受试者、seed、组别；点击对应“启动单项 →”。
3. 弹窗再次显示运行标识，核对无误。
4. E最终评价默认不勾选。只有架构、超参、预算及统计方案已锁定且获得最终评价授权时，才勾选“同时执行最终Session E评价”。不勾选时只评价validation，后续汇总会因缺测试结果而报告不完整。
5. 输入准确文字 `启动单个正式实验`，点击“启动此实验”。
6. 只会执行该项。计划SHA错误、计划不存在或输出目录已存在都会拒绝启动。

界面没有批量执行270项或修改正式seed/超参的功能。操作台检查不代替人工科学审核，也不会自动验证原锁中每一个源码hash。

## 10. 任务与日志：状态与指标

任务通常启动后自动跳转到本页。点击任务“查看”可显示命令、退出码、日志、训练曲线以及可用JSON。

| 状态 | 解释 | 建议动作 |
|---|---|---|
| 运行中 | 子进程尚未结束 | 查看日志，等待；不要重复启动 |
| 已完成 | 退出码0 | 再核对输出完整性与指标含义 |
| 失败 | 非零退出码 | 保存错误和输出目录，定位原因 |
| 停止中 | 已发SIGTERM、等待退出 | 等待状态变化，不启动第二任务 |
| 已停止 | 经操作台停止后进程退出 | 保留日志，不能视为完成结果 |
| 服务中断 | 服务重启时原任务未完成 | 核查主机进程/GPU，不能直接假设已停止 |

界面日志只显示末尾100KB，训练曲线只显示末尾300条记录。完整原始日志位于 `data/console/<任务ID>.log`，完整逐更新指标位于任务输出目录的 `train.jsonl`。

梯度L2、loss和优化器步数来自实际日志；短程loss下降不能支持负迁移或科学显著性。任务详情可以展开评价JSON，查看random25/outside14等具体指标，注意物理单位V。

## 11. 停止、退出与失败后恢复

Linux/WSL2上点击运行任务旁的“停止”，操作台向它拥有的进程组发送SIGTERM。会保留已有日志和输出；没有精确断点续训或自动重试。

建议退出顺序：停止任务 → 等待状态成为已停止或已完成 → 查看主机占用 → 终端Ctrl+C退出服务。不要用关闭网页来停止任务。

若服务被直接关闭或主机异常，子进程可能继续运行；重启操作台只把原任务标为interrupted，不会接管旧进程。先检查：

```bash
ps -ef | rg 'eeg_transfer|pytest'
nvidia-smi
```

`rg`不存在时可用系统进程查看器。不要按模糊名称批量杀进程。原生Windows使用任务管理器核查，网页停止功能没有平台保证。

正式失败运行需保留原目录，从同一个plan/seed在全新的输出路径重启，记录替代路径；不得删除失败结果后假装首跑，也不得更换seed或挑最好重跑。当前网页不提供修改输出路径功能，需要维护者建立新的清单输出映射并保留版本记录，不能直接反复点旧运行。

## 12. 使用朋友的GPU主机

1. 朋友在Linux或WSL2主机获取相同commit，创建本机虚拟环境。
2. 按PyTorch官方安装选择器安装与驱动兼容的CUDA版本，再安装 `-e '.[test]'`。不要照搬CPU虚拟环境或猜测CUDA包版本。
3. 核对实际可用性：

```bash
nvidia-smi
.venv/bin/python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

4. 私下同步或按官方来源重下 `data/raw`、`data/processed`、训练归一化、`data/plans`，并同步与计划匹配的审计和清单。只Git拉取不够。转移后核验SHA和路径，不能只复制文件夹名称。
5. 先测试与T-only短程冒烟，记录硬件/依赖差异；CPU/GPU不保证逐位一致。
6. 在朋友主机项目目录启动服务，可在 `tmux` 中保持运行。
7. 自己电脑建立SSH转发，替换用户名与主机地址：

```bash
ssh -N -L 8765:127.0.0.1:8765 username@gpu-host
```

8. 自己电脑打开 `http://127.0.0.1:8765`，填写朋友主机终端生成的令牌。

本机8765已占用时用 `ssh -N -L 8766:127.0.0.1:8765 username@gpu-host`，本机浏览器访问8766。关闭SSH转发会断开页面连接，不停止GPU主机任务。主机SSH账号、网络/VPN和密钥由双方配置，操作台不会自动获取远程权限。

## 14. 常见故障速查

| 现象/错误 | 可能原因 | 处理 |
|---|---|---|
| 找不到 `eeg_transfer.console` | 不在正确环境、未更新work分支 | 核对项目目录和commit，用本项目Python安装依赖 |
| `.venv`无效或Windows找不到python.exe | 复制了Linux环境或Python版本不合适 | 保留并重命名旧环境，再本机重建，不删研究数据 |
| 网页无法打开 | 服务未启动/端口错误/SSH转发断开 | 看终端URL；先在服务主机核对，再查转发 |
| 401/请填写访问令牌 | 旧令牌或复制错误 | 从当前服务终端重新复制，通过右上角更新 |
| Address already in use | 已有控制台占用端口 | 检查旧实例或更换`--port`，不要同目录启动双实例 |
| CONNECT 403 | 云端代理策略拦截 | 核查当前实例生效的允许域名；包含官方与Graz目标 |
| 已有派生数据，拒绝覆盖 | Sxx.npz已存在 | 使用重新审计；需修复时保留原文件与独立迁移记录 |
| 已有任务在运行 | 单队列保护 | 等待或按第11节停止，不刷新重试启动 |
| 历史清单计划文件未恢复 | 只拉取Git，没有gzip包 | 恢复匹配计划，或审核后生成新清单 |
| 计划校验和不符 | 包改变、复制错误或清单混用 | 保留两版核验；不直接改hash求通过 |
| 输出已存在 | 以前运行留下结果/失败目录 | 保留历史，以新映射路径重启相同plan/seed |
| 无GPU或torch CUDA为False | 无驱动、CPU版torch或设备未分配 | 在真正GPU主机检查驱动和对应torch，允许CPU短程验证 |
| 测试失败FileNotFoundError | 当前数据/计划未随Git传来 | 记录真实失败，补齐文件；不照抄历史通过数 |
| 任务已完成但statistics为null | 正式结果不完整 | 读取missing_runs；不做选择性样本统计 |
| 日志长时间不变 | 下载/计算中、网络等待或进程异常 | 查看完整日志、进程和设备占用，再决定停止 |
