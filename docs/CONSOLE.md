# EEG项目Web操作台

操作台与训练运行在同一主机。默认只监听127.0.0.1；不需要Node、数据库或新增Python依赖，使用项目虚拟环境即可。

```bash
cd /workspace/About-EEG
.venv/bin/python -m eeg_transfer.console
```

打开 http://127.0.0.1:8765 ，输入终端显示的 `Access token`。令牌默认每次启动随机生成，仅存在服务内存和当前浏览器标签页的sessionStorage。也可以由主机管理员通过 `EEG_CONSOLE_TOKEN` 环境变量提供固定令牌；不要提交到Git。页面/API不提供任意命令终端，不收集SSH密码。不要直接把Python开发服务暴露到公网。

## 功能

- 概览：九人数据存在状态、当前计划清单、真实完成计数、GPU显存/利用率（有nvidia-smi时）。存在状态不是新的SHA校验。
- 数据：历史/恢复审计、已有MAT重新导入审计；缺失受试者可逐人从官方来源下载，核对历史原始SHA后建立规范派生文件。拒绝覆盖已有规范派生数据。新审计输出独立目录。
- 协议：只读JSON配置、历史协议锁、统计协议。网页不会改动科研超参数。
- 实验：查看所有清单，按受试者/组筛选；生成9人×3seed×10组新计划但不训练；每次明确启动一个正式运行。正式启动验证计划SHA，拒绝已有输出目录。Session E评价默认关闭，需明确勾选。
- 任务：固定操作入口、一次一个任务、进程组停止、持久任务状态、尾部日志、loss曲线、梯度及评价JSON。
- 报告：审计/工程报告原文、现有results中的评价/manifest/runtime/gate。新结果汇总由清单驱动，缺失时不输出统计推断。

下载、生成全量计划可能耗时；已有文件不重复下载。4步冒烟固定使用S01 V2/A2，只评价预先限定的T验证trial，不评价E，不修改协议锁。测试入口运行原有pytest，其中固定工程测试可能评价E以校验管线，不能用于模型选择。

## 使用朋友的GPU

1. 在朋友的Linux或WSL2主机克隆/同步此项目，安装相应CUDA版本PyTorch及本项目依赖。不能复制云端CPU虚拟环境。
2. 单独同步被忽略的 `data/raw`、`data/processed`、`data/plans`，或用操作台逐人下载并生成新计划；同步恢复报告中的新清单才能使用相应计划。对照同seed、数据划分和评价mask保持不变。
3. 在该主机启动上述服务。可用tmux保持运行，不依赖浏览器窗口持续打开。
4. 在自己的电脑建立转发（替换用户名和主机地址）：

```bash
ssh -N -L 8765:127.0.0.1:8765 username@gpu-host
```

5. 本机浏览器打开 http://127.0.0.1:8765 ，使用朋友主机终端产生的访问令牌。关闭SSH转发仅影响网页连接，不停止GPU主机上的训练。连接主机的SSH/VPN仍由双方配置，本操作台不会自动解决云端TCP访问权限。

## 运行边界

仅支持Linux/WSL2进程组管理。一个项目目录只能启动一个控制台实例，不支持多用户调度、跨主机队列或精确断点续训。服务重启会把未完成任务标成interrupted，不伪装完成、不自动重试；异常退出后子训练进程可能仍在运行，应先检查主机进程/GPU占用再启动新任务。正常停止任务保留目录和日志，正式实验若需重跑，应在新的清单输出路径中保留同plan/seed，不覆盖或挑最好seed。

任务状态和原始控制台日志位于忽略目录 `data/console/`；审计/新清单位于 `reports/console/`，训练输出位于 `results/rq1-console-*`。控制台没有自动发布托管版本，因为训练必须在拥有数据和GPU的主机执行。

云端浏览器预览目前遇到基础设施错误：`relay could not open browser port 4173: timed out waiting for relay readiness`。API、Python/JS静态检查及真实训练管线验证已执行；视觉与点击流程未完成浏览器实测。

## Windows一键启动包

从仓库下载 `downloads/EEG-console-launcher.zip`，解压后双击 `START_CONSOLE.cmd`。放到项目根目录时自动定位；放在其他位置时输入项目完整路径（如 `E:\About-EEG`）。ZIP仅包含脚本和说明，完整项目仍需先拉取work分支。

脚本自动创建项目独立`.venv`、检查依赖，缺失时执行`pip install -e ".[test]"`，然后启动网页服务；无需激活环境，不修改旧`bci_env`，不自动训练、不配置CUDA。若已有无效或Linux版`.venv`，提示手动重命名，不删除。当前已做ZIP完整性及脚本内容核对，尚无Windows CMD实机验证。
